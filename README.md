# 瞬間英作文

日本語文を見て英語を声で答え、その場で正誤が分かる学習アプリです。

## 起動方法

Node.js が必要です。追加のパッケージのインストールは不要です。

1. `start.bat` をダブルクリックします。黒い画面が開きます。
2. `http://localhost:5173` が開きます。Chrome が入っていれば Chrome で開きます。
3. 使っている間は、黒い画面を開いたままにします。終わるときは、この画面を閉じます。

`http://localhost:5173` に接続できないときは、アプリが起動していません。`start.bat` をダブルクリックしてください。すでに起動している場合は、ブラウザだけが開きます。

コマンドで起動する場合は、次のとおりです。

```bash
npm start
```

`index.html` を直接開いても動きません。問題データの読み込みとマイクの利用に、`localhost` か HTTPS が必要なためです。

## 使い方

1. レベル、問題数、制限時間を選び、「始める」を押します。
2. 日本語文が出たら、マイクボタンを押して英語で答えます。話し終えると自動で判定します。
3. 正解なら模範解答を再生して次の問題へ進みます。
4. 惜しい場合と不正解の場合は、違う語を確認して「再挑戦」か「次へ」を選びます。

声が使えないときは「文字で答える」でキーボードから回答できます。

## 判定の仕組み

判定は [js/judge.js](js/judge.js) にまとめています。回答と正解例を次のようにそろえてから比べます。

- 小文字化と記号の除去
- 短縮形の展開(`I'm` → `I am`)
- 数字表記の統一(`500` → `five hundred`)
- 同音語の統一(`there` と `their` など)

認識候補は上位3件まで調べ、最も正解例に近い候補で判定します。

| 判定 | 条件 |
| --- | --- |
| 正解 | そろえた後の回答が、正解例のいずれかと一致 |
| 惜しい | 一致はしないが、類似度0.7以上 |
| 不正解 | 類似度0.7未満、無回答、または時間切れ |

類似度は「1 − 単語の編集距離 ÷ 正解例の語数」です。

## 学習記録

- 正解率と苦手な問題は、各問の初回の結果で記録します。再挑戦の結果は記録しません。
- 直近の結果が正解でない問題を「苦手な問題」として扱います。次に初回で正解すると外れます。
- 記録はブラウザの localStorage に保存します。ブラウザや端末をまたいでは共有されません。サイトデータを消すと記録も消えます。

## 問題の追加方法

[data/questions.json](data/questions.json) に次の形式で追加します。

```json
{
  "id": "L1-021",
  "level": 1,
  "pattern": "現在形",
  "ja": "私は毎朝コーヒーを飲みます。",
  "answers": [
    "I drink coffee every morning.",
    "I have coffee every morning."
  ]
}
```

- `id` は重複しない値にします。
- `answers` には、正解として認める言い方をすべて書きます。短縮形の違いは書かなくても正解になります。
- 例文は、市販の教材から転載せず、新しく作ります。
- 問題数を変えた場合は、[tests/questions.test.js](tests/questions.test.js) の問題数も変更します。

追加した文の音声ファイルは、次の手順で作ります。すでにあるファイルは作り直しません。

```bash
npm install --no-save --no-package-lock kokoro-js @breezystack/lamejs
```

```bash
node tools/generate-audio.mjs
```

音声ファイルがない文は、ブラウザの音声合成で読み上げます。

## 模範解答の音声

模範解答は `audio/` の音声ファイルを再生します。iOS 27 の iPhone の実機では、ブラウザの音声合成は処理が進んでも音が出ないことがありましたが、音声ファイルの再生は録音の直後でも音が出たためです。

音声は [Kokoro-82M](https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX)(Apache-2.0)で作りました。

## 対応ブラウザ

対象は PC の Chrome です。音声認識に対応していないブラウザでは、自動で文字入力に切り替わります。

PC と Android のブラウザでは、音声認識のために音声が提供元のサーバーへ送られることがあります。このアプリ自身は音声を保存しません。

## スマートフォンで使うには

スマートフォンのマイクを使うには、アプリを HTTPS のサイトとして公開する必要があります。`localhost` はその端末自身を指すため、PC で起動したアプリをスマートフォンから声で使うことはできません。

このアプリは静的なファイルだけで動くため、`index.html`、`css`、`js`、`data` を静的サイトのホスティングサービスに置けば公開できます。

### iPhone と iPad で動きが違う点

iOS 27 の Safari は、ブラウザの音声認識が2回目以降に音を受け取らなくなります([WebKit bug 321436](https://bugs.webkit.org/show_bug.cgi?id=321436))。実機の診断では、間隔をあける、先にマイクを開く、読み上げを挟むなどの回避策はいずれも効きませんでした。そのため、iPhone と iPad ではこのアプリがマイクを録音し、端末の中で文字に変換します。

- 音声は端末の外へ送りません。
- 学習を始めるときに音声認識モデル(Moonshine base、約70MB)を読み込みます。初回はダウンロードが必要で、以後はブラウザのキャッシュから読み込みます。
- ライブラリは jsDelivr、モデルは Hugging Face から取得します。どちらにも音声は送りません。
- 話している間は、そこまでの音声を繰り返し変換して途中の文字を表示します。端末の処理が終わるのを待って次を始めるので、更新の間隔は端末の速さで変わります。途中の文字は後から変わることがあります。
- 話し終えてから約1.2秒で録音を止め、全体を変換し直した結果で判定します。

声の入力が動かないときは、「文字で入力」を押してキーボードのマイクを使えます。英語のキーボードに切り替えてから話してください。

認識に失敗したときは、「詳細」を開くと調査用の情報を確認して、コピーできます。

## テスト

```bash
npm test
```

## 既知の制限

- 発音は評価しません。認識された文字列だけで判定します。
- 音声認識が文法を補って聞き取った場合、文法の誤りが正解になることがあります。
- 登録していない言い換えは、正しい英文でも惜しいか不正解になります。納得できないときは「この回答を正解にする」で追加できます。追加した正解例は、そのブラウザの中だけで有効です。
- 同音語は同じ語として扱うため、文字入力でも `there` と `their` の違いは不正解になりません。
- `'d` は常に `would` として扱います。`had` の短縮形として使った場合は、正解例と一致しないことがあります。

## ファイル構成

| パス | 内容 |
| --- | --- |
| `index.html`、`css/style.css` | 画面 |
| `js/app.js` | 画面の表示と学習の流れ |
| `js/judge.js` | 正誤判定 |
| `js/progress.js` | 出題の選択と学習記録の更新 |
| `js/speech.js` | 音声認識と読み上げの入り口。PC と Android の音声認識 |
| `js/device-speech.js`、`js/transcribe-worker.js` | iPhone と iPad の録音と、端末の中での文字への変換 |
| `js/diagnostics.js` | 端末の判別と調査用の記録 |
| `js/audio-files.js`、`audio/` | 模範解答の音声ファイルとその名前の決まり |
| `tools/generate-audio.mjs` | 模範解答の音声ファイルを作る道具 |
| `js/storage.js` | 学習記録の保存 |
| `data/questions.json` | 問題データ(3レベル、計50問) |
| `tests/` | 自動テスト |
| `server.js`、`start.bat` | ローカルサーバーと起動用ファイル |
